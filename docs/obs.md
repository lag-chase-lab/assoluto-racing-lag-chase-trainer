# OBS設定とリプレイ運用

OBSのGUIから設定します。このプロジェクトは既存のOBS設定ファイルを直接書き換えません。

## 1. 専用プロファイルとシーン

1. 「プロファイル」→「新規」で比較録画専用プロファイルを作成
2. 「シーンコレクション」→「新規」で比較録画専用コレクションを作成
3. 比較用シーンを1つ作成

## 2. 映像

「設定」→「映像」で設定します。

| 項目 | 標準値 |
|---|---:|
| 基本（キャンバス）解像度 | 1920×540 |
| 出力（スケーリング）解像度 | 1920×540 |
| FPS | 30 |

端末の横長アスペクト比をそのまま残したい場合は、右映像が歪まない幅へキャンバスを広げ、基本解像度と出力解像度を同じ値にします。Pixel 7aなどでは1920×540より広いキャンバスになることがあります。左右を無理に同じ幅へ引き伸ばさず、実際の位置比較がしやすい配置を優先してください。

## 3. 録画

「設定」→「出力」→出力モード「詳細」で設定します。

| 項目 | macOS | Windows |
|---|---|---|
| 録画形式 | MKV | MKV |
| 映像エンコーダー | Apple VT H.264ハードウェア | NVENC / Quick Sync / AMD H.264の利用可能なもの |
| 音声トラック | 1を選択 | 1を選択 |

OBSは録画時に少なくとも1つの音声トラック選択を要求します。音声不要の場合でもトラック1を選び、「音声ミキサー」の全ソースをミュートしてください。

MKVは録画中の異常終了に比較的強い形式です。QuickTime Playerで必要な場合は、録画後に「ファイル」→「録画の再多重化」でMP4へ変換します。確認再生にはVLCを推奨します。

## 4. ソース

### macOS

「macOS画面キャプチャ」を2つ追加し、種類をウィンドウキャプチャにします。

- 左：Android Emulator（`qemu-system-aarch64` または `qemu-system-x86_64`）
- 右：`Android - Assoluto Racing`

### Windows

「ウィンドウキャプチャ」を2つ追加します。

- 左：Android Emulator（`qemu-system-x86_64.exe`）
- 右：scrcpy（`Android - Assoluto Racing`）

ウィンドウ枠を含めず、ゲーム映像部分が見やすいようにクロップ・拡大します。配置が完成したらソースをロックしてください。

## 5. 起動順の注意

OBSは起動後に作られたウィンドウを候補一覧へすぐ反映しない場合があります。毎回次の順番が確実です。

1. Android Emulator
2. scrcpy
3. OBS

OBSを先に起動した場合は、scrcpyを起動してからOBSを再起動し、右ソースのプロパティで `Android - Assoluto Racing` を選び直します。録画中はOBSを再起動できないため、開始前に必ず左右を確認してください。

## 6. リプレイバッファ

1. 「設定」→「出力」→「リプレイバッファ」
2. 「リプレイバッファを有効にする」をオン
3. 最大リプレイ時間：30秒
4. 最大メモリ：512MB
5. 「設定」→「ホットキー」
6. 「リプレイバッファを保存」に好みのキーを設定

毎回「録画開始」→「リプレイバッファ開始」の順に押します。確認したい場面の直後に保存ホットキーを押すと、通常録画を止めずに直前30秒が別のMKVへ保存されます。

## 7. USB切断

USBが切れるとscrcpyウィンドウ自体が終了します。再接続監視スクリプトは実機を検出すると同じタイトルでscrcpyを再起動しますが、ウィンドウIDは変わります。

OBS右側が戻らない場合：

1. 右側ソースのプロパティを開く
2. 新しい `Android - Assoluto Racing` を選択
3. 位置・サイズ・クロップは変更しない

切断中の右映像は空白または最後のフレームになり、その区間を後から復元することはできません。
